# v1.19.0 — Approval-Bound Contract Snapshots

**Release date:** 2026-09-11

**State:** Released as `v1.19.0`.

## Scope

- `/contract-refine` now prepares exact proposed owner bytes outside active
  owners and binds the complete sorted `finalOwners` path/role/content-hash
  manifest into the approved proposal.
- Snapshot creation always requires an explicit proposal and approval,
  including first baseline adoption. A clean or committed Git state is not
  treated as human acceptance.
- Snapshot verification binds owner identity, proposal and approval identity,
  compiled source/rule digests, and the embedded ledger. Same-path byte or
  whitespace substitution, additions, deletions, renames, role changes, and
  ignored active owners fail closed.
- `/contract-align` requires a verified snapshot. Evaluation receipts bind
  exact in-repository target paths and bytes, while verdict rejects stale
  targets, stale owners, mismatched evaluation hashes, malformed or ungrounded
  review evidence, incomplete assessment, and violations.
- Missing, mixed valid-plus-missing, and outside-repository target requests are
  rejected before content evaluation instead of silently reducing scope.
- Heuristic review is conditionally delegated to a fresh read-only reviewer
  when the current parent authored, refined, disputed, or implemented the
  relevant claim. Review remains evidence rather than authority or a vote.
- The deterministic core, CLI, matching helpers, and snapshot identities are
  split into focused zero-dependency TypeScript modules below 1,000 lines each.

### Disposable live Agy trial

One fresh disposable Git sandbox was exercised through Agy `1.2.1` with Gemini
3.8 Flash High:

1. `/contract-refine` inspected live source counterexamples, prepared proposed
   owner bytes outside active owners, reported the complete final manifest and
   proposal hash, and stopped before mutation.
2. After exact scoped approval, Agy wrote only the pre-hashed owner bytes,
   created the approval-bound snapshot, verified it, and stopped without
   touching implementation source.
3. `/contract-align` evaluated two exact target files, received a violation
   review, made the two required default-export/default-import edits, obtained a
   fresh pass review, and produced `ALIGNED` for one heuristic rule and two
   targets.
4. Main independently replayed snapshot verification and verdict, then proved
   that pre-capture owner substitution and post-evaluation target drift both
   fail closed with exit 2.
5. A fresh verifier found a mixed valid-plus-missing target scope reduction.
   The CLI was corrected to validate every target before evaluation; focused
   and full tests passed, and the verifier's bounded recheck returned PASS.

The sandbox, Agy panes, and related processes were removed after evidence
collection.

## Limitations

- Approval metadata and decision locators are cooperative records, not
  cryptographic authentication or protection against an agent able to rewrite
  every local artifact and claimed provenance.
- Distinct recorded reviewer IDs do not independently establish host-attested
  reviewer-session identity.
- The mechanical verdict proves only the exact snapshot, targets, deterministic
  checks, and bounded review entries assessed. It does not establish universal
  semantic correctness or human product acceptance.
- No runtime supervisor, automatic continuation, compaction recovery, OS
  sandbox, installed-plugin refresh, live MemFS migration, or remote updater is
  added by this release.
