# v1.15.2 — Descendant-Safe Migration Rollback

**Release date:** 2026-08-26

`v1.15.2` keeps the v1.15 rollback guarantee valid after approved
post-migration curation. It preserves v1.15.1's runtime identifier validation
and adds exact pre-rollback snapshots for every migration-owned path.

## Defect

The original rollback required the migration commit itself to remain at
MemFS `HEAD`. The first approved post-release curation correctly created a new
descendant commit, after which rollback would fail closed even though the
migration archive and parent receipts remained intact.

## Fix

- Require the named migration commit to be an ancestor of current clean HEAD
  instead of requiring exact HEAD equality.
- Before restoration, archive every present current migration-owned path and a
  manifest with explicit present/absent state plus SHA-256 for present content
  under the migration archive.
- Preserve later curation archives and other post-migration paths.
- On write/commit failure, restore all migration-owned and newly created
  rollback-archive paths to the actual descendant HEAD—not the older migration
  commit.
- Keep invalid/non-ancestor commits fail-closed.

rollback manifest, and finished clean. Live MemFS itself was not rolled back.

## Upgrade

For a local checkout, pull `v1.15.2` and run:

```bash
./plugins/agy-memory-layer/scripts/update.sh
```

For a cached one-line installation, rerun the root installer before invoking
`/update`.
