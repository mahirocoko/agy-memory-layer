# v1.18.0 — Hardened Contract Ledger & Honest Deterministic Alignment

**Release date:** 2026-09-09

**State:** Released as `v1.18.0`.

`v1.18.0` redesigns the Contract Ledger (`scripts/contract-ledger.ts`) and `/contract-align` skill to eliminate false-positive compliance claims, prevent premature "100% aligned" declarations, and provide mechanical evidence gates for pairing workflows.

## Core Improvements & Additions

- **Honest Rule Coverage Accounting**:
  - Replaced binary check status with structured `RuleCoverage` (`evaluated`, `unevaluated`, and `ratio`).
  - Added strict `EvaluatorId` types: `no-interface`, `inline-dictionary`, `max-lines`, `forbidden-pattern`, `required-pattern`, `comment-taxonomy`.
  - Added `EvaluationVerdict`: `deterministic-clean`, `deterministic-violations`, and `contract-dispute`.
  - Completely eliminated misleading `✓ Code is 100% aligned` phrasing from CLI output and documentation.
  - Implemented **Exit Code 3 (`REVIEW_REQUIRED`)**: When coverage < 1.0, the CLI exits with 3 to enforce that deterministic clean checks do not masquerade as total compliance.

- **Deterministic Evaluators & `Check:` Directives**:
  - `no-interface`: Prohibits TypeScript `interface` declarations in favor of `type` aliases.
  - `inline-dictionary`: Flags inline `const FOO_MAP = { ... }` that belong in centralized constants or translation catalogs.
  - `max-lines`: Flags files exceeding configured line count limits, properly handling trailing newlines.
  - `forbidden-pattern`: Disallows forbidden AST or token patterns with regex syntax error protection.
  - `required-pattern`: Enforces required exports or tokens with fail-closed validation.
  - `comment-taxonomy`: Requires section comment headers to strictly match allowed taxonomy (requiring `_` prefix, e.g. `// _State`).

- **Mechanical Verdict Gate (`contract-ledger.ts verdict`)**:
  - Enforces independent heuristic review (`review.json`) for unevaluated architectural rules.
  - Whitelists valid verdicts (`pass`, `not-applicable`, `violation`); rejects typos and unknown strings with exit 3.
  - Strictly rejects non-clean eval states (exiting with 4 on `contract-dispute`).
  - Rejects zero-file evaluation and conflicting duplicate review entries (failing closed with exit 2).

- **Hub Invariant Protection & Scope Relativization**:
  - Invariants from `AGENTS.md` and hub sections can never be outvoted by spoke majority drift.
  - In `evaluateCodeAgainstContract`, target paths are relativized against `ledger.repoRoot` before matching in `matchesGlob`, supporting scoped directives (e.g. `app/routes/**/*.tsx`) on absolute paths.
  - Supports comma-separated globs in `scope=` directive attribute.
  - Majority threshold is calculated against applicable files (`entry.applicableCount`) rather than diluted across all scanned files.

- **Hardened via Cursor Fable 5.1 Thinking High Double Audit**:
  - Audited and verified across two independent Cursor Fable 5.1 review passes.
  - Resolved all identified findings (B1–B8 and F1–F4) with comprehensive unit tests in `tests/contract-ledger.test.ts`.
