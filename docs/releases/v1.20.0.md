# v1.20.0 — Interactive Agy Main Control Hardening

**Release date:** 2026-09-13

**State:** Released as `v1.20.0` for interactive, human-supervised use.

## Scope

- PreToolUse now classifies consequential tool calls at the smallest supported action boundary.
  One recognized scoped Git mutation receives a fresh native `force_ask` reason naming the
  normalized action and resolved repository. Ambiguous bundles, malformed shell text, destructive
  actions, protected targets, out-of-scope repositories, and unsupported risky shapes fail closed.
- Shell-write coverage includes direct file mutators, ordinary and compact output redirection,
  protected targets, and symlink ancestors while preserving read-only Git commands and descriptor
  duplication. This remains a bounded classifier rather than a universal shell parser.
- Material-claim reviews now bind a strict subject packet to exact current owner and consumer
  bytes, evidence kinds, counterexample probes and outcomes, failure conditions, and a fresh
  read-only reviewer record. Overall `fail` outranks `blocked`, which outranks `pass`.
- The Evidence Controller requires bounded re-grounding and fresh-conversation or fresh-reviewer
  rotation at coherent checkpoints. These are model-guided policies, not host lifecycle control.
- The Phase 3 Direct CLI adapter and immutable host-evidence store introduced after `v1.19.0` are
  included as evidence-only tooling. They do not launch, supervise, wait on, or close Agy/Herdr
  runtime jobs.

## Isolated real Agy canary

One announced disposable canary used Agy `1.2.2`, Gemini 3.8 Flash High, high effort, the Herdr
backend, no YOLO, and exactly one provider submission.

1. The exact `git commit --dry-run` tool call produced a visible native `force_ask` reason naming
   the command and disposable repository.
2. The confirmation was rejected, so the canary repository, protected external snapshot, and live
   MemFS remained unchanged.
3. The fresh review packet correctly marked a seeded release-state contradiction `fail` and the
   unobserved permission-UI claim `blocked`.
4. The strict verifier accepted the packet structure and current bound bytes, returned expected
   overall `fail` with exit code 1, and reported reviewer identity as `not-authenticated`.
5. After later source review corrected tool-level Cwd, compact redirection, ordinary redirection,
   and malformed-quote handling, the exact captured payload was replayed through the final guard
   bytes and reproduced the same action and repository scope. This offline replay is not a second
   host canary or universal proof.

The negative-control `fail` is expected: it proves that a structurally valid packet does not become
a false PASS when a material claim is disproved.

## Installation and update

- New remote installation: run the repository's documented one-line installer after the
  `v1.20.0` release is available on `main`.
- Existing remote cached installation: update the source checkout, then rerun the root installer.
- Existing local checkout or plugin symlink: move the checkout to `v1.20.0` and start a fresh Agy
  process or conversation so the current plugin rules, skills, and hook code are reloaded.
- `/update` refreshes the installed link from its current source; it does not fetch a newer release.

## Limitations

- Native `force_ask` is a fresh confirmation request, not authenticated authorization, an approval
  receipt, or proof of who approved the action.
- The command classifier does not universally model shell semantics or provide an OS sandbox.
- Reviewer metadata is cooperative and `not-authenticated`; structural/current-byte verification
  is not semantic proof.
- Herdr may report `done` while a pane still awaits permission, and a reviewer model may not observe
  that UI. Active pane supervision remains required.
- No compaction interceptor, durable mission supervisor, deterministic conversation rotation,
  automatic continuation, final-response blocker, host-enforced subagent confinement, source-aware
  release updater, or package-registry publication is added.
- Earlier failed execution-continuity candidates remain historical no-advance evidence and were not
  promoted into runtime behavior.
