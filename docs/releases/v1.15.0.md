# v1.15.0 — Layered Memory & Safe Curation

**Release date:** 2026-08-26

`v1.15.0` replaces one large always-on global/project memory pair with a
committed-HEAD layered projection while preserving safe legacy fallback. It
also adds explicit destination-backed curation and a receipt-bound,
provenance-preserving migration/rollback path.

## Layered projection

- Focused `system/` owners are injected for global and current-project context.
- `reference/` files remain discoverable through a bounded index without
  injecting their bodies.
- All projection comes from committed MemFS `HEAD`; dirty memory stays out of
  prompt context.
- Layout selection is repository-wide. Any coexistence of layered and legacy
  active owners fails closed instead of projecting a partial repository.
- Existing clean legacy repositories continue to project without migration.
- The one canonical working hypothesis and 1,400-token strict health contract
  remain intact.

## Safe curation and migration

- Every non-empty source body unit, including headings, receives exactly one
  disposition.
- Active/reference/duplicate destinations must contain either the exact source
  line or one explicitly named summary line.
- Historical/rejected units require explicit policy; rejection remains
  human-approved only.
- Exact source snapshots, SHA-256 receipts, the complete disposition ledger,
  plan hash, and changed-path manifest are committed under migration/curation
  archives.
- Apply, curation approval, and rollback revalidate `HEAD`, plan receipts,
  source receipts, the shared writer lock, and clean repository state.
- Failed write/commit paths restore declared memory paths and staging state.
- Rollback restores only migration-owned paths from the recorded parent and
  keeps the provenance archive.

## Writer and lifecycle hardening

- Cross-process locking now uses atomic exclusive lock-file creation.
- Existing stale or unreadable locks fail closed and require deliberate manual
  recovery; they are never stolen automatically.
- Initializer, Dream, approval, Letta import, backup restore, migration,
  curation, and rollback use the shared lock and scoped restoration where they
  mutate MemFS.
- New installations bootstrap layered global owners.
- Both installer entry points refuse a non-empty non-Git memory directory
  rather than silently initializing ownership over unknown files.
- Search, Palace, persona, compaction, health, and documentation understand
  layered and legacy layouts through the same projection owner.

## Upgrade

For a local checkout, pull `v1.15.0` and run:

```bash
./plugins/agy-memory-layer/scripts/update.sh
```

For a cached one-line installation, rerun the root installer so its source
checkout advances before invoking `/update`.
