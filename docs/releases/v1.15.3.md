# v1.15.3 — Layered Memory Palace Topology

**Candidate date:** 2026-08-26

**State:** Source candidate; not committed, tagged, or published.

`v1.15.3` corrects Memory Palace after the v1.15 layered migration. Runtime
projection already loaded each focused Human document correctly, but Palace
joined those bodies into one `system/human/*` card and therefore hid the real
subtree from users.

## Fix

- Build Core Memory entries from every committed global and current-project
  system document instead of one aggregated Human card.
- Render nested `system/human/` and `system/human/prefs/` folders with exact
  selectable file paths, per-file descriptions, bodies, token/character counts,
  and Git detail.
- Preserve flat legacy Core nodes.
- Refuse Palace generation when legacy and layered active owners conflict.
- Omit empty current-project groups rather than inventing project owners.
- Read the displayed Palace version from `plugin.json` instead of a stale
  hard-coded badge.

## Acceptance Contract

Completion requires generated-artifact and real-browser evidence in addition
to source tests: every layered Core node must select its exact path, content,
description, and commit; legacy fallback and mixed-layout refusal must pass;
current-project data must not leak from another project; and nested layout must
remain usable without horizontal overflow at narrow width.
