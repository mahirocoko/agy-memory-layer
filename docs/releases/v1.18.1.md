# v1.18.1 — Project-Owned Contract Binding

**Release date:** 2026-09-09

**State:** Released as `v1.18.1`.

## Scope

- Interface mentions, interface permissions with `I`-prefix naming, and preferences for type aliases no longer implicitly bind the `no-interface` evaluator.
- Prefer explicit `Check: no-interface` directives. Backward compatibility is limited to complete normalized action or intent fields: `never declare interface` and `do not declare interface`. Qualified or compound prose requires explicit binding or review.
- The repository's actual Thai type-only rule now has an explicit check scoped to TypeScript and TSX files.
- `/contract-align` examples are conditional on active project rule IDs, owners, and scopes, not plugin implementation conventions. `/contract-refine` requires semantic conflict review before enforcement.
- Release manifests and assertions are synchronized. The integration report footer now refers to observed validation counts rather than duplicating a stale skill count.

## Verification

- Focused contract-ledger suite: **19/19** passing, including six disposable-HOME CLI fixtures and an actual Thai hub-rule regression.
- `pnpm test`: **60/60** Node tests passing (59 focused cases plus the integration runner); **11/11** integration scenarios passing.
- `pnpm check`: TypeScript, layer boundaries, and Biome passing.
- No new coverage measurement; the README coverage table remains the historical `v1.15.4` snapshot.

## Boundaries

- No semantic conflict engine: mechanical verification does not establish that prose rules agree or that a submitted review is semantically correct.
- No `I`-prefix evaluator: permitting interfaces does not mechanically validate their naming. Unevaluated naming and preference rules still require review.
- Interface declaration detection remains regex-based, not a complete TypeScript semantic analysis.
- Verification is source/fixture evidence, not fresh real-host semantic acceptance or live installation/migration evidence.
- These notes describe the bounded patch, not a cumulative inventory of unpublished intermediate versions. Repository notes for intermediate versions do not establish corresponding remote GitHub releases.
