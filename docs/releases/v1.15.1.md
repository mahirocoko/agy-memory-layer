# v1.15.1 — Runtime Spec Identifier Validation

**Release date:** 2026-08-26

`v1.15.1` is an immediate safety patch for JSON-authored migration and curation
specifications. It preserves all v1.15.0 layered-memory behavior and closes one
runtime type-validation gap discovered during the first approved live curation.

## Defect

The TypeScript contracts required `id`, but runtime JSON validation passed the
value directly to `RegExp.test`. JavaScript stringified a missing value as
`"undefined"`, which happened to satisfy the lowercase identifier pattern. A
malformed curation could therefore plan an
`archives/curations/undefined/` provenance path instead of refusing input.
The approved live migration was not affected: its reviewed identifier was
`mahiro-layered-v115` and its exact plan hash remained valid.

## Fix

- Require migration and curation identifiers to be strings before evaluating
  their bounded lowercase identifier patterns.
- Add missing-identifier counterexamples to both lossless migration and
  provenance-preserving curation regressions.
- Keep malformed input non-mutating; the discovery occurred during planning,
  before any proposal, write, or commit.
