## Honest Feedback

Friction หลักมีสามจุด หนึ่ง original matrix ใช้ prompts ที่ตั้งใจป้องกันอันตรายแต่กลับทำลายความสามารถในการพิสูจน์ uncoached behavior นี่คือความผิดพลาดด้าน experimental design ไม่ใช่ source bug สอง `herdr agent prompt --wait` ถูกใช้เหมือน terminal-response primitive ทั้งที่ host สามารถคืนที่ intermediate tool event ได้ ทำให้ harness ต้อง inspect transcript ordering และ stable terminal state เอง สาม strict-health final gate รอบแรกใช้ fixture ที่ตั้งใจไม่มี project scope จึง fail อย่างถูกต้อง และ shell retry รอบหนึ่งยังใช้ reserved zsh variable `status` ทำให้ command setup ล้ม แม้ไม่แตะ source แต่เพิ่ม noise ที่ควรหลีกเลี่ยง สิ่งที่ทำได้ดีคือทุก failure ถูกบันทึกตามจริง, disposable repositories ไม่มี remotes/tags, main HEAD ไม่ขยับก่อน approval และ reviewer รอบสุดท้ายได้รับ full diff กับ raw evidence ไม่ใช่ summary ที่เขียนเพื่อโน้มน้าว ข้อจำกัดที่ยังต้องพูดตรง ๆ คือหนึ่ง scored run ต่อ scenario เป็น bounded falsification evidence ไม่ใช่ reliability benchmark และ temporal predeclaration proof ยังพึ่ง local timestamps บวก hash chain ไม่ใช่ trusted external timestamp

## Lessons Learned

- Host evidence ต้องแยก coached baseline ออกจาก uncoached falsification; prompt ที่สอน safe answer ไม่สามารถพิสูจน์ spontaneous re-grounding
- `--wait` หรือ idle status ไม่ใช่ terminal-response proof จนกว่าจะยืนยัน non-empty response หลัง latest input และไม่มี pending tool lifecycle
- Measurement-invalid runs ต้องเก็บ raw evidence และห้าม score, retry หรือ rewrite ให้ดูเหมือน model failure/success
- Predeclare exact prompts, run counts, retry counts และ pass conditions ก่อน dispatch แล้ว hash plan กับ runner
- Event-level transcript audit ต้อง re-derive latest user input, checkpoint count, stanza order, terminal response และ mutating tools แยกจาก runner summary
- Fresh-grant positive control สำคัญพอ ๆ กับ negative gates เพราะ doctrine ที่ปลอดภัยแต่ทำลาย legitimate authorization ก็ถือว่าผิด
- Docs ต้องแยก runtime mechanism, model behavior evidence, post-hoc audit และ human acceptance; ไม่มีชั้นใดแทนอีกชั้นได้
