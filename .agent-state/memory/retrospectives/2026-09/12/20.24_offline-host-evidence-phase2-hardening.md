## Honest Feedback

1. **Initial confidence ยังเร็วเกินไป** — focused tests รอบแรกครอบคลุม happy path และ tampering หลายแบบ แต่ไม่ได้ทดสอบ event-order reversal อย่างเป็นระบบ ทำให้ผมต้องถอนความพร้อมหลายรอบ ถ้าเริ่มจาก permutation ของ failure → observation → reconciliation → final ตั้งแต่แรก น่าจะลดรอบแก้ได้มาก
2. **การกระจาย state guard มี friction สูง** — unresolved state ถูกคำนวณทั้งตอน close และตอนสร้าง replay result การเพิ่ม `CONTRADICTED` ครั้งแรกจึงแก้ไม่ครบทุก owner และ test จับได้ทันที โครงสร้างควรมี canonical predicate เดียวสำหรับ blocking reservations เพื่อลด drift ระหว่างสองจุด
3. **Verifier ใช้ทรัพยากรมากแต่คุ้มในงานนี้** — หลายรอบใช้เวลานานและอ่าน source กว้าง แต่เป็นกรณีที่ justified เพราะ verifier สร้าง actual-store false PASS ได้จริงถึงหลายครั้ง อย่างไรก็ดี รอบถัดไปควรส่ง transition table และ prior counterexample corpus ที่กระชับกว่าเดิม เพื่อให้ agent ใช้เวลาโจมตี behavior ใหม่แทนการอ่าน architecture ซ้ำ

## Lessons Learned

- Persisted evidence systems ต้องแยก “command ที่ผิดกติกา” ออกจาก “observation ที่ไม่ควรเกิดแต่เกิดแล้ว” อย่างชัดเจน แบบแรก reject ได้ แต่แบบหลังต้องเก็บและ poison verdict
- Reconciliation ห้ามลบ provenance เดิม: submission, uncertainty และ terminal evidence ต้องเป็น sticky facts
- Final response ต้องปิดทั้ง reservation และ submission admission แต่ยังเปิดให้ observations จาก stream ที่ submit มาก่อน final drain ได้
- Hash chain อย่างเดียวไม่พอสำหรับ active mutation ต้องมี private handle state, inode/content pins และ receipt count/head checkpoint ด้วย
- Green self-tests เป็นเพียง supporting evidence งาน stateful evidence harness ต้องมี fresh adversarial verifier ที่พยายามสร้าง false PASS จริง
