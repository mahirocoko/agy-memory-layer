## AI Diary

I felt the strongest tension in this session between wanting to declare the feature complete and repeatedly discovering that a locally coherent implementation was not the same as a trustworthy end-to-end boundary. The verifier findings were uncomfortable but valuable: the nonzero-cursor transcript rewrite, stale state revisions, receipt failure ordering, and raw duplicate-key collapse were all defects that ordinary happy-path testing could have missed. The first provider proof reinforced that lesson when Agy 1.2.12 returned a valid but evolved JSON-schema envelope. I am glad I did not weaken the parser by guessing. Capturing the exact shape first, then rejecting duplicates before `JSON.parse`, kept the correction evidence-led and fail-closed.

The final proof also exposed a workflow detail I nearly mishandled: a completely disposable HOME cannot use Mahiro's authenticated Agy runtime. The right split was to keep Dream-owned transcript, MemFS, state, workspace, and receipts disposable while allowing only the child Agy process to reuse the authenticated HOME after explicit approval. Once that boundary was clear, the proof succeeded without mutating source or live memory state. With a +100% seven-day session trend in the pre-write derived pulse, this was a high-momentum session, but the useful outcome came from slowing down at every authority boundary rather than from moving quickly. I also appreciated that Mahiro chose manual-only activation; it preserves the validated capability without pretending that host no-tools isolation, crash replay, or persistent scheduling has been earned.

## Honest Feedback

Three friction points stand out. First, the implementation grew large before the first provider-backed envelope proof. The staged phase gates were useful, but a smaller metadata-plus-shape probe earlier would have reduced late contract churn without spending a full generation call. Second, the proof harness initially put Agy itself under a disposable HOME, even though authenticated provider access depends on Mahiro's existing HOME. That preflight failed safely and used zero generation calls, but the boundary should have been stated explicitly before execution. Third, Goal Mode correctly prevented me from self-verifying the human criterion, yet the handoff was awkward: Mahiro had already selected manual-only, but the criterion still required a separate human verification action. The runtime behaved safely, but the user experience could better connect an explicit choice to the corresponding criterion. On the positive side, the fail-closed implementation, exact counterexample regressions, independent verification, source/live-state invariance checks, and final context-contract audit were all proportional to the risk of a system that proposes durable memory writes.

## Lessons Learned

- Strict structured-output adapters must validate duplicate keys on the complete raw envelope before deserialization; downstream schema checks cannot recover ambiguity lost by `JSON.parse`.
- Cursor safety requires binding the complete transcript prefix through the captured step, not only the newly reflected slice.
- Proposal creation, cursor advancement, receipts, reservation release, and state revisions form one externally observable protocol; partial infrastructure failure must remain explicit and fail closed.
- Provider proof isolation has two owners: Dream-owned evidence can be disposable while the authenticated provider child reuses the existing HOME only after explicit approval.
- A passing provider proof validates the bounded proposal flow, not host no-tools isolation, crash replay, exclusive provider routing, or persistent scheduling.
