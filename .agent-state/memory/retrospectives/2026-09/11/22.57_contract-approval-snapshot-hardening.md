**Type**: Architecture / Security Hardening / Runtime Verification

## Session Summary

This session replaced the contract workflow's circular trust chain with an approval-bound frozen
snapshot. A proposal now binds the complete final active-owner manifest—path, role, and exact content
hash—before approval. Snapshot creation always requires that proposal and an explicit approval,
including first baseline adoption; Git cleanliness is no longer treated as human acceptance.
Evaluation binds exact in-repository target bytes, and verdict rejects stale targets, stale owners,
malformed or mismatched reviews, and incomplete heuristic coverage. The final workflow was exercised
through a disposable real Agy 1.2.1 / Gemini 3.8 Flash High refine → approval → snapshot → align run,
then challenged by a fresh verifier. The verifier found one mixed-valid/missing-target scope hole;
Main fixed it, added the regression, reran all checks, and received a final PASS with bounded
provenance caveats.

Before writing this retrospective, derived pulse data counted 36 prior retrospectives across eight

## Architecture Decisions

- Approval binds the complete exact final owner manifest, not merely an item summary or dirty path.
- Every first snapshot requires explicit baseline adoption; a clean or committed contract is not
  proof of human acceptance.
- Existing verified snapshots are reusable while owner bytes remain unchanged; source-only edits do
  not require repeated contract approval.
- Evaluation identity includes exact target paths and bytes. Every explicit target must exist and be
  contained in the repository before any target content is evaluated.
- Heuristic review is evidence, not authority or a vote. Fresh read-only review is conditionally
  required when the current parent authored, refined, disputed, or implemented the claim.
- The workflow deliberately stops short of cryptographic approver identity, host-attested reviewer
  identity, runtime supervision, or hostile-agent resistance.

## AI Diary

I started this work thinking the main defect was an overly permissive semantic review loop, but the
session repeatedly showed that identity comes before interpretation. The first implementation looked
strong: snapshot hashes, evaluation hashes, reviewer evidence, and stale-target checks all passed.
The real Agy run also behaved correctly. It would have been easy for me to call that enough. The
advisor's counterexample exposed the deeper flaw: the approval was attached to a proposal summary and
owner path, while the final bytes were captured only afterward. A cooperative agent followed the
instructions, but the mechanism did not prove that the bytes approved were the bytes frozen. I felt
the same uncomfortable pull that appeared in the execution-continuity experiment—the system I had
just built produced persuasive green evidence, and I had to actively search for a way that evidence
could still be true while the desired guarantee was false.

The second important moment came after the full real-host flow passed. The fresh verifier supplied a
mixed valid-plus-missing target and showed that the missing path silently disappeared. That was a
small implementation detail with a large scope consequence: a review receipt could remain identical
while the caller believed it covered more files. I am glad I did not dismiss it as an input-quality
problem. The correct fix was cheap and local—validate every requested path before collection—yet it
closed a real proof gap. What improved in my own behavior was not simply “run more reviewers.” I used
specialists at specific uncertainty boundaries, replayed their claims against exact bytes, and stopped
adding review once the counterexample was closed. The result is narrower and more honest than a
universal compliance engine, but it now proves the exact bounded claim it reports.

## What Went Well

- The workflow was tested through a real Agy host rather than accepted from source tests alone.
- Main did not trust model summaries; proposal hashes, owner bytes, receipts, diffs, reviewer IDs,
  snapshot verification, and final verdict were independently replayed.
- Two material counterexamples—proposal-to-final-byte substitution and mixed missing targets—were
  incorporated as deterministic regressions rather than left as narrative caveats.
- The implementation stayed zero-dependency and was split into scripts below the repository's
  1,000-line guidance without breaking the original CLI entrypoint.
- Temporary sandboxes, Agy panes, and related processes were closed and removed before release prep.

## What Could Improve

1. Define the exact approval object and final-byte invariant before the first implementation pass;
   path-level approval was too weak despite sounding scoped.
2. Test mixed input sets early. All-missing and all-valid cases did not expose silent scope reduction.
3. Keep executable receipt examples in the skill from the start so Agy does not repeatedly inspect
   large implementation files to infer JSON schema.
4. Preserve one concise machine-readable real-host evidence bundle when release evidence should be
   independently inspectable after temporary sandbox cleanup.

## Honest Feedback

The biggest friction was the amount of iteration required to separate cooperative workflow behavior
from actual mechanical guarantees. Several writer passes reported completion while leaving the CLI
module oversized, and one implementer returned while its full test command was supposedly still
running even though no process remained. Main had to inspect each diff and rerun every critical check.
The second friction was Herdr's transient lifecycle reporting: `done` sometimes appeared while an Agy
child reviewer was still active, so a single status event was never sufficient. The third friction was
evidence retention. The disposable sandbox was excellent for preventing product-repo pollution, but a
verifier could not retrieve Main's completed background-command transcript by task ID later and had
to treat that receipt access as blocked. None of these problems justify more routine reviewers or a
runtime supervisor in this scope. Better predeclared invariants, stable terminal collection, compact
receipt preservation, and one adversarial mixed-input test would have reduced both latency and token
cost substantially while preserving the same quality bar.

## Lessons Learned

- A proposal digest is only meaningful when it includes the exact final bytes or their complete
  canonical manifest.
- Git cleanliness proves repository state, not human approval.
- Exact-target proof must reject every unresolved requested target before evaluation; silently
  shrinking scope invalidates the caller's claim even when evaluated files are bound correctly.
- Real cooperative success and fail-closed negative controls are both required before describing a
  contract workflow as hardened.
- Distinct reviewer IDs and approval receipts remain evidence, not authenticated identities.
