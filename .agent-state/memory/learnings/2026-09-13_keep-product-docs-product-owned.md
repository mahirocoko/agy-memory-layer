# Keep Product Documentation Product-Owned

**Tags:** documentation, privacy, ownership, context-contracts

## Intent

Keep public and always-active repository documentation focused on the current product rather than
turning it into a timeline of internal investigations or external case studies.

## Trigger

A session produces a retrospective, benchmark, attribution report, experiment, or external-project
evidence that may be useful to retain or link from current product documentation.

## Action

Classify the artifact before writing. Preserve bounded evidence in a dated supporting owner using
neutral descriptors. Update the README or current project overview only when the evidence changes a
current capability, installation contract, architecture owner, supported behavior, or known gap
that their readers need.

## Boundary

Do not include proprietary external-project identities, paths, or case-specific summaries in public
or always-active product surfaces. This does not prevent a current product capability or release
from carrying its own directly relevant evidence.

## Rationale

Discoverability does not automatically establish relevance. Keeping current owners product-focused
reduces context drift, protects external identities, and prevents session history from accumulating
as public documentation clutter.
